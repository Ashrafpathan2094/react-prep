**React.js Frontend Developer (2-3 Years Experience) - Mock Interview Questions and Model Answers**

**1. Functional vs Class Components**

**Q:** What is the difference between functional and class components in React? When should you use one over the other?

**A:** Functional components are simpler and use React Hooks to manage state and lifecycle methods. Class components were more common before Hooks, requiring more boilerplate (e.g., `constructor`, `this.state`). In modern React (post v16.8), functional components are preferred due to conciseness, better performance, and cleaner code. Class components are still useful in legacy projects.

---

**2. State Management in Large-Scale Applications**

**Q:** How would you manage the state in a large-scale React application?

**A:** For global state management in large apps, I’d use Redux Toolkit. It avoids prop drilling, offers a well-defined architecture, and supports features like middleware and dev tools. Unlike `useContext`, Redux state persists better across refreshes and scales more cleanly.

---

**3. useEffect Hook**

**Q:** Explain the useEffect hook and its lifecycle behavior.

**A:** `useEffect` handles side effects in functional components. It runs after the component renders. If you provide a dependency array, it runs only when those dependencies change. An empty array means it runs once after the initial render. It can also return a cleanup function to clean up subscriptions or timers.

```jsx
useEffect(() => {
  setUserState("new user");
  return () => setUserState("clean user");
}, []);
```

---

**4. Keys in React**

**Q:** Why are keys important when rendering lists in React?

**A:** Keys help React identify which items have changed, been added, or removed. They improve performance and prevent rendering bugs. Keys must be unique and consistent across renders. Using indices as keys is discouraged unless list order never changes.

---

**5. Server-Side Rendering (SSR)**

**Q:** What is SSR and how does it improve performance and SEO?

**A:** SSR renders the HTML on the server before sending it to the client. It reduces time-to-first-byte and allows search engines to crawl content more effectively, improving SEO and performance.

---

**6. Controlled vs Uncontrolled Components**

**Q:** What's the difference between controlled and uncontrolled components in React?

**A:** Controlled components use React state to manage inputs (`value` and `onChange` props). Uncontrolled components use refs to access the DOM directly. Controlled components are preferred for consistency and better form control.

---

**7. useMemo and useCallback**

**Q:** What are `useMemo` and `useCallback` used for?

**A:** `useMemo` memoizes the result of a computation, `useCallback` memoizes the function itself. Useful for preventing unnecessary recalculations or re-renders in components.

```jsx
const memoizedValue = useMemo(() => expensiveCalculation(data), [data]);
const memoizedFn = useCallback(() => doSomething(id), [id]);
```

---

**8. Higher-Order Components (HOC)**

**Q:** What is a higher-order component and when would you use one?

**A:** An HOC is a function that takes a component and returns a new component with additional behavior. Use cases include authentication guards, layout wrappers, and reusable logic injection.

```jsx
const withLayout = (Component) => (props) => (
  <Layout>
    <Component {...props} />
  </Layout>
);
```

---

**9. useMemo vs React.memo**

**Q:** What’s the difference between `useMemo` and `React.memo`?

**A:** `useMemo` memoizes values inside a component. `React.memo` wraps entire components to avoid re-renders if props don’t change. They serve different but complementary purposes.

---

**10. Error Boundaries**

**Q:** What are Error Boundaries in React?

**A:** Error boundaries catch JavaScript errors in child components and render a fallback UI. They only catch render errors in class components, not event handlers. `Suspense` handles lazy loading but is different from error boundaries.

```jsx
<ErrorBoundary>
  <MyComponent />
</ErrorBoundary>
```

---

**11. useEffect vs useLayoutEffect**

**Q:** What is the difference between `useEffect` and `useLayoutEffect`?

**A:** `useEffect` runs after the DOM is painted. `useLayoutEffect` runs synchronously after DOM mutations but before paint. Use `useLayoutEffect` when you need to measure or update the DOM before it’s visible (e.g., animations or measuring dimensions).

---

**12. Code Splitting and Lazy Loading**

**Q:** How do you implement code splitting in React?

**A:** Use `React.lazy` for dynamic imports and `Suspense` for fallback UIs. Route-based splitting (e.g., React Router with lazy components) helps load only needed code.

```jsx
const About = React.lazy(() => import('./About'));

<Suspense fallback={<Loader />}>
  <About />
</Suspense>
```

---

**13. Performance Optimization**

**Q:** What steps would you take to improve performance in a React app?

**A:**

* Use `useMemo`, `useCallback` to avoid recalculations
* Add pagination to large lists
* Use keys properly
* Lazy load routes and components
* Break large components into smaller ones
* Minimize unnecessary re-renders

---

**14. Team Collaboration Practices**

**Q:** How do you ensure clean collaboration in a large frontend team?

**A:**

* Only one dev per component at a time
* Provide proper KT and documentation
* Follow existing code style and architecture
* Promote use of shared/common components
* Use pull requests and reviews for consistency
